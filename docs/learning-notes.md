# 챙김 개발하면서 배우기

## 1. 화면과 데이터는 역할이 달라요

홈과 일정 상세는 같은 일정을 보여줍니다. 각 화면이 따로 복사한 값을 관리하면 상세에서 체크해도 홈에는 옛날 값이 남을 수 있어요.

`ScheduleStore`가 데이터를 관리하고 변경을 알려주면, `ListenableBuilder`가 연결된 화면을 다시 그립니다.

살펴볼 곳: `lib/data/schedule_store.dart`의 `put`, `notifyListeners`와 `lib/screens/home_screen.dart`의 `ListenableBuilder`.

## 2. 화면 갱신과 기기 저장은 별개예요

화면의 값을 바꾸는 것만으로는 앱을 종료한 뒤 데이터가 남지 않습니다. 기기에 저장하고 다시 읽는 처리가 필요해요.

이번 버전에서는 작은 데이터를 JSON 문자열로 바꾸어 기기에 저장합니다. JSON은 제목·날짜·준비물을 다른 곳에서도 읽을 수 있는 텍스트로 표현하는 방식이에요. 이 저장 방식은 초기 버전용이며, 데이터가 늘어나면 데이터베이스와 백업을 검토합니다.

저장에 성공한 뒤 화면에 반영하므로, 저장에 실패했는데 성공한 것처럼 보이는 문제를 피합니다.

살펴볼 곳: `lib/models/schedule.dart`의 `toJson`, `fromJson`과 `LocalScheduleStorage`.

## 3. 비슷해 보이는 상태도 구분해야 해요

준비물을 모두 체크했어도 실제 신청은 아직 안 했을 수 있습니다. 그래서 준비물 완료와 일정 진행 단계를 별개로 관리합니다.

`enum ScheduleStage`는 진행 단계에 들어갈 수 있는 값을 네 가지로 제한합니다. 오타로 엉뚱한 상태가 저장되는 것을 줄여줘요.

## 4. 테스트는 실제 규칙을 확인해요

확인하는 규칙: 앱을 다시 열었을 때 복원, 저장 실패 시 기존 값 유지, 기한이 지나도 자동 완료하지 않기, 준비물 체크가 홈에 반영되기, 완료 일정 제외하기.

## 5. 같은 디자인 규칙을 모으면 수정이 쉬워져요

색·폰트·모서리·입력창 스타일은 `lib/design/app_theme.dart`에 모아뒀어요. 이런 공통 규칙을 '디자인 토큰'이라고 불러요. 한곳에서 바꾸면 여러 화면이 함께 일관되게 바뀝니다.

## 6. 앱 화면의 Widget과 홈 화면 위젯은 달라요

Flutter에서 말하는 Widget은 화면을 구성하는 부품이고, Android 홈 화면 위젯은 운영체제가 앱 밖에서 표시하는 별도 화면이에요.

Flutter의 `WidgetBridge`가 제목·기한·남은 준비물 같은 최소 표시 데이터를 `MethodChannel`로 Android에 전달합니다. Android의 `RemoteViews`는 저장한 스냅샷을 읽어 앱이 꺼져 있어도 표시합니다. 일정 데이터 원본은 앱의 저장소가 관리하고, 위젯 데이터는 다시 만들 수 있는 표시용 사본이에요.

살펴볼 곳: `lib/platform/widget_bridge.dart`와 `android/app/src/main/kotlin/com/example/my_first_app/ChaengimWidget.kt`.

## 7. 위젯을 누를 때는 데이터 로딩 순서가 중요해요

앱이 이미 켜져 있을 수도 있고, 완전히 새로 실행될 수도 있어요. 위젯이 전달한 일정 ID를 잠시 보관했다가 저장소를 불러온 뒤 상세 화면을 엽니다. 이런 특정 화면으로 바로 이동하는 동작을 '딥링크'라고 해요.

## 8. 예약 알림은 앱 타이머와 달라요

앱 안의 `Timer`는 앱 프로세스가 종료되면 함께 멈춰요. 예약 알림은 `AlarmManager`에 맡겨서 Android가 나중에 Receiver를 실행하게 합니다. 알림을 표시할 권한과 알림을 예약하는 동작은 별개예요.

`PendingIntent`는 '나중에 이 동작을 실행해 주세요'라고 운영체제에 맡기는 실행권이에요. 일정을 수정하거나 삭제할 때 같은 ID의 실행권을 찾아 취소해야 예전 알림이 남지 않습니다.

## 9. '하루 전'이 항상 24시간 전은 아니에요

일광 절약 시간제가 있는 지역에서는 하루가 23시간 또는 25시간일 수 있어요. 그래서 날짜에서 하루를 빼고 현지 오전 9시를 만드는 방식으로 계산합니다. Dart와 Android 양쪽에 이 규칙을 검증하는 테스트를 두었습니다.

살펴볼 곳: `lib/models/reminder_plan.dart`와 Android의 `ReminderPlanner.kt`.

## 10. 테마는 색상 묶음으로 관리해요

바탕·글자·강조색을 팔레트로 묶어 둔 것이 디자인 토큰이에요. Flutter의 `ThemeExtension`으로 화면마다 같은 팔레트를 읽습니다. 테마를 바꾸면 앱 전체가 새로 그려지고, 같은 색상을 Android 위젯에도 전달해요. 미리보기는 팔레트만 보여주고 실제 선택을 저장하지 않아요.

살펴볼 곳: `lib/design/app_skin.dart`, `lib/data/appearance_store.dart`.

## 11. 구매 버튼과 구매 권한은 달라요

결제창이 열렸다고 구매가 끝난 것은 아니에요. 취소·승인 대기·연결 실패가 있을 수 있어요. 스토어 구매를 검증한 뒤 얻는 권한을 entitlement라고 합니다. 챙김은 `chaengim_plus` 권한 하나로 광고 제거와 유료 테마를 함께 열어요. 구매 복원도 같은 권한을 다시 확인하는 과정입니다.

테스트의 가짜 스토어로 보류·취소·복원 동작을 확인하지만, 실제 판매 전에는 Google Play 테스트 계정에서도 확인해야 해요. 광고 역시 개발 중에는 수익이 발생하지 않는 테스트 광고로 확인합니다.
