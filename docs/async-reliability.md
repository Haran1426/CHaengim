# 지연·새로고침 오류 처리

## 일정은 네트워크와 분리

일정·준비물·메모는 기기에 저장합니다. 네트워크가 끊겨도 광고·구매 조회 실패 때문에 일정을 지우거나 저장 성공을 취소하지 않습니다. 서버 동기화나 클라우드 백업 기능은 아직 없습니다.

## 새로고침과 저장

- 홈·일정·마이 화면에서 아래로 당겨 다시 불러올 수 있습니다.
- 같은 시점의 중복 읽기는 한 번의 작업으로 합칩니다.
- 저장 중 요청한 새로고침은 저장 완료 후 읽습니다.
- 첫 데이터 로딩이 끝나기 전에는 위젯·알림에 빈 스냅샷을 보내지 않습니다. 실제로 일정이 없는 경우에는 정상적으로 빈 상태를 동기화합니다.
- 읽기 실패 시 메모리에 남아 있는 마지막 일정을 보여주고 재시도를 안내합니다. 다시 읽기에 성공하기 전에는 편집을 잠가 기존 저장 내용을 덮어쓰지 않게 합니다.
- 로컬 읽기는 10초 후 오류 안내로 전환합니다. 시간 초과한 읽기가 나중에 끝나도 재시도 결과를 덮어쓰지 않습니다.
- 로컬 쓰기는 임의로 시간 초과 처리하거나 자동 반복하지 않습니다. 쓰기는 나중에 성공할 수도 있으므로 실패했다고 단정하고 재시도하면 안 됩니다.

## 위젯·알림·테마

위젯과 알림 전달은 서로 독립적으로 진행합니다. 각 대기는 8초 뒤 안내로 전환할 수 있으며 일정 저장 결과는 유지합니다. 같은 버전의 중복 전달은 합치고, 새 스냅샷은 앞선 실제 호출이 끝난 뒤 전송합니다. 오래된 호출이 뒤늦게 완료돼 최신 상태를 덮어쓰는 순서 역전을 막습니다.

`Future.timeout`은 원래 작업을 취소하지 않습니다. 따라서 대기 시간만 줄이고 내부 실행 순서는 유지합니다. 실제 호출이 영구히 돌아오지 않으면 다음 전달도 완료할 수 없으므로 앱 재시작과 기기 로그 확인이 필요할 수 있습니다. [Dart 공식 설명](https://api.dart.dev/dart-async/Future/timeout.html).

테마를 읽는 중 앱에 복귀해도 기본 테마를 먼저 위젯에 적용하지 않습니다. 테마 읽기에 실패하면 저장된 위젯 색상을 임의로 바꾸지 않습니다.

알림 설정 화면은 오래된 상태 응답을 무시하고 최신 요청만 반영합니다. 설정 적용 중에는 중복 적용을 막으며, 상태 조회가 응답하지 않으면 재시도 안내를 보여줍니다. 사용자가 응답하는 Android 권한 창을 임의로 시간 초과시키지는 않습니다.

## 구매·광고 조회

각 스토어 초기화 대기·상태 조회·상품 조회에는 15초 제한을 둡니다. 지연 안내 후 다시 조회할 수 있습니다. 구매 권한 알림이 조회 요청보다 나중에 도착했다면, 오래된 조회 결과가 그 알림을 덮지 않습니다. 중복 새로고침은 같은 작업의 완료를 기다립니다.

결제창이 열린 요청은 조회와 구분합니다. 결제 완료·취소·승인 대기는 SDK 응답으로 판단하며, 시간 초과를 이유로 결제를 자동 재요청하지 않습니다. 광고 SDK는 초기화에 실패한 작업을 영구히 재사용하지 않고 이후 다시 시도할 수 있게 합니다.

## 검증 범위

`test/async_reliability_test.dart`와 `test/platform_retry_test.dart`에서 지연 읽기·쓰기, 시간 초과 후 늦은 응답, 동시 요청, 위젯 지연 중 알림 전달, 테마 로딩 중 복귀, 실제 새로고침 실패 화면과 재시도를 확인합니다.

이 검증은 실제 스토어 계정·상품 설정, 제조사별 절전 정책, 모든 네트워크 상태를 보증하지 않습니다. 출시 전 실기기·Google Play 테스트 트랙 검수가 별도로 필요합니다.
