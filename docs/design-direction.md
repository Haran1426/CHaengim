# 챙김 화면과 위젯

## 레퍼런스와 해석

[Things](https://culturedcode.com/things/)의 여백, 단계별 정보 강조, 해야 할 일에 집중하는 목록 구성을 참고합니다. 화면을 복제하지 않고, 챙김의 마감·준비·제출·결과 대기 흐름에 맞춰 재구성했습니다.

- 종이빛 바탕 `#F6F4EF`, 짙은 초록 `#244C3F`, 연두 `#E0EEAC`
- Paperlogy 400/500/600/700을 앱에 포함해 오프라인에서도 같은 글꼴 사용
- 제목·마감·남은 준비물이 먼저 보이도록 배치. 핵심 화면의 본문·안내는 14px 이상으로 유지하고 보조 글씨의 대비도 확보
- 같은 정보를 문장·숫자·진행 설명으로 반복하지 않기. 홍보 문구와 내용 없는 구역은 홈에서 표시하지 않기
- 의미가 같은 요소는 같은 색·간격·둥근 모서리 사용

폰트 출처와 조건: [Paperlogy 공식 저장소](https://github.com/Freesentation/paperlogy), SIL Open Font License 1.1. 원본 폰트와 라이선스를 함께 포함합니다.

## 화면 순서

홈: 날짜 → 오늘의 챙김 → 가장 급한 일정 → 바로 체크할 준비물 최대 3건 → 다음 일정 최대 2건. 준비물·다음 일정이 없으면 해당 구역은 표시하지 않습니다. 위젯 안내는 상단 버튼과 마이에서 엽니다.

일정: 검색 → 진행 상태·기간 → 카테고리 → 기한순 목록.

상세: 제목·기한 → 진행 단계 → 준비물 → 후속 일정 → 메모·참고 링크. 준비물 체크나 후속 일정 추가로 진행 단계를 자동 변경하지 않습니다.

일정 카드는 카테고리·D-day·제목·마감·남은 준비물로 구성합니다. 완료 비율은 진행 막대로 보여주되 같은 숫자를 작은 문장으로 반복하지 않습니다. 준비 완료는 일정의 최종 완료와 구분합니다.

마이는 테마·플러스·위젯·알림 메뉴와 기기 저장 안내만 보여줍니다. 등록 화면에서는 입력 항목 위의 장식성 소개 문구를 생략합니다.

## Android 위젯

- 소형 '한눈에': 가장 급한 미완료 일정 1건, D-day, 남은 준비물.
- 중형 '모아보기': 크기에 따라 2~3건, 진행 단계. 좁게 줄이면 소형 레이아웃 사용.
- 일정 탭: 해당 상세. `+`: 등록. 빈 상태 탭: 등록.
- 최종 완료는 제외. 기한 지난 미완료는 '기한 지남'. 일정이 없으면 빈 상태와 추가 버튼.
- 저장 직후 Android에 최소 표시용 스냅샷을 전달. 앱을 종료해도 Android가 표시·갱신.
- 30분 간격 갱신 요청, 날짜·시간대 변경 및 재부팅·앱 업데이트 시 다시 계산. 운영체제의 절전·강제 종료·런처 정책에 따라 갱신이 지연될 수 있으며 정확한 자정 실행을 보장하지 않습니다.
- Android 8 이상에서 지원 런처의 위젯 고정 요청 사용. 미지원 시 수동 추가 안내.
- Flutter 기본 딥링크는 끄고 위젯 전용 경로로 연결해 실행 중·종료 상태를 모두 처리.

구현 기준: [Android 위젯 개요](https://developer.android.com/develop/ui/views/appwidgets/overview), [갱신 정책](https://developer.android.com/develop/ui/views/appwidgets/advanced).

## 검수용 앱

`tool/preview.dart`는 예시 데이터를 넣는 별도 진입점입니다. **반드시 별도 applicationId 속성과 함께** 빌드하세요. 기존 앱과 저장 공간이 분리됩니다.

```sh
flutter build apk --debug -t tool/preview.dart --android-project-arg=chaengimPreview=true
```

일반 앱은 `flutter build apk --debug`로 빌드합니다. 검수용 APK가 생성된 뒤에는 일반 APK를 다시 빌드해야 합니다.

클라우드 백업은 아직 제공하지 않습니다. 위젯 빠른 체크는 기획서의 기본안대로 상세 화면으로 이동해 처리합니다. 이후 추가한 마감 알림의 규칙은 [알림 동작과 검수](reminders.md)에 정리했습니다.

## 초기 검수 기록

- `flutter analyze`: 지적 사항 없음. `flutter test`: 10개 통과.
- 320px 너비·글자 크기 1.6배에서 홈·일정 목록·위젯 가이드 오버플로 없음.
- Android 에뮬레이터에 설치해 앱 폰트·홈·상세 화면 확인.
- 실제 런처에 소형 2×2·중형 4×2 추가 확인. 중형을 세로로 확대해 3건 표시 확인.
- 위젯에서 첫 번째/두 번째 일정 상세 진입, +로 등록 화면 진입 확인.
- 앱 프로세스 종료 후 위젯으로 새 프로세스를 시작해 상세 진입 확인.
- 준비물 체크 후 남은 개수 동기화, 최종 완료 변경 후 해당 일정이 위젯에서 제외됨을 확인.
- 실물 휴대폰, 제조사별 런처, 재부팅 및 장시간 절전은 추가 검증 필요.

예시 데이터로 찍은 화면: [홈](screenshots/home.png), [상세](screenshots/detail.png), [기본 크기 위젯](screenshots/widgets.png), [확대한 중형 위젯](screenshots/widgets-expanded.png). 사용자 앱 데이터와 분리된 검수용 앱에서 촬영했습니다.

## 1.0.3 읽기 부담 줄이기

- 홈의 소개 문구·3종 집계·빈 준비물/다음 일정 안내·위젯 홍보 카드를 제거했습니다.
- 카드의 준비물 완료/남은 개수 중복 설명을 제거했습니다. 진행 막대의 읽기 보조 설명은 유지합니다.
- 일정 목록·마이·등록 화면의 장식성 소개 문구를 생략하고, 마이는 설정 메뉴 중심으로 줄였습니다.
- 상세의 중복 단계 그림을 없애고 진행 단계 선택을 유지합니다. 준비물 완료가 자동으로 최종 완료가 되지는 않습니다.
- 핵심 화면의 작은 11~13px 문구를 14px 이상으로 키우고 기본 본문은 16px로 조정했습니다. 보조 글자색을 진하게 해 5개 테마 바탕과의 계산 대비가 5.7:1 이상이 되게 했습니다.
- 코드 검사 지적 사항 0건, 테스트 43개 통과. 기존 320px·글자 1.6배 화면 검사와 저장·준비물 체크 흐름을 확인했습니다.
- 별도 검수용 앱의 예시 데이터로 Android 17 ARM64 변환 실행에서 [홈](screenshots/home-readable.png)·[마이](screenshots/my-readable.png)를 확인했습니다. 일반 배포용 APK는 예시 데이터를 넣지 않은 기본 진입점으로 다시 빌드합니다.
