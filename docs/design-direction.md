# 챙김 화면과 위젯

## 휴대폰 하단 안전 영역 (1.0.7)

일정 등록·상세, 테마, 플러스, 알림 설정, 위젯 안내 화면의 본문을 `SafeArea(top: false)`로 감쌉니다. 앱 바가 처리하는 상단 영역은 유지하고, 기기가 보고하는 하단·좌우 안전 영역 안에 스크롤 화면을 배치합니다. 홈·일정·마이의 앱 하단 탭 바는 기존 NavigationBar의 안전 영역 처리를 사용합니다.

하단 시스템 영역 64px를 적용한 등록 화면에서 스크롤 영역과 저장 버튼이 안전 영역 안에 있는지 검사했습니다. 키보드 높이 300px로 전환한 뒤에도 저장 버튼까지 스크롤할 수 있음을 확인했습니다. 전체 Flutter 테스트 47개 통과.

## 레퍼런스와 해석

[Things](https://culturedcode.com/things/)의 여백, 단계별 정보 강조, 해야 할 일에 집중하는 목록 구성을 참고합니다. 화면을 복제하지 않고, 챙김의 마감·준비·제출·결과 대기 흐름에 맞춰 재구성했습니다.

- 종이빛 바탕 `#F6F4EF`, 짙은 초록 `#244C3F`, 연두 `#E0EEAC`
- 제목·본문·버튼·숫자를 Noto Sans KR 400/500/600/700으로 통일. 앱에 포함해 오프라인에서도 같은 글꼴 사용
- 제목·마감·남은 준비물이 먼저 보이도록 배치. 핵심 화면의 본문·안내는 14px 이상으로 유지하고 보조 글씨의 대비도 확보
- 같은 정보를 문장·숫자·진행 설명으로 반복하지 않기. 홍보 문구와 내용 없는 구역은 홈에서 표시하지 않기
- 의미가 같은 요소는 같은 색·간격·둥근 모서리 사용

폰트 출처와 조건: [Google Fonts의 Noto Sans KR](https://fonts.google.com/noto/specimen/Noto+Sans+KR), [공식 라이선스](https://github.com/google/fonts/blob/main/ofl/notosanskr/OFL.txt). SIL Open Font License 1.1 원문을 앱의 오픈소스 라이선스에도 표시합니다. 배포 파일과 해시는 [폰트 자산 기록](../assets/fonts/README.md)을 참고하세요.

## 화면 순서

홈: 날짜 → 오늘의 챙김 → 이번 주 마감 → 가장 급한 일정 → 바로 체크할 준비물 최대 3건 → 다음 일정 최대 2건. 준비물·다음 일정이 없으면 해당 구역은 표시하지 않습니다. 진행 중인 일정이 없을 때는 종류별 빠른 추가를 제공합니다. 위젯 안내는 상단 버튼과 마이에서 엽니다.

주간 날짜를 누르면 해당 날짜의 미완료 마감 일정으로 이동합니다. 날짜 필터는 목록에서 해제할 수 있고, 기간 필터를 바꾸면 초기화됩니다. 이번 주는 기기의 달력 날짜 기준 월요일부터 일요일까지입니다. 완료 일정은 마감 점·건수에서 제외합니다.

일정: 검색 → 진행 상태·기간 → 카테고리 → 기한순 목록.

상세: 제목·기한 → 진행 단계 → 준비물 → 후속 일정 → 메모·참고 링크. 준비물 체크나 후속 일정 추가로 진행 단계를 자동 변경하지 않습니다.

일정 카드는 카테고리·D-day·제목·마감·남은 준비물로 구성합니다. 완료 비율은 진행 막대로 보여주되 같은 숫자를 작은 문장으로 반복하지 않습니다. 준비 완료는 일정의 최종 완료와 구분합니다.

마이는 테마·플러스·위젯·알림 메뉴와 기기 저장 안내만 보여줍니다. 등록 화면에서는 입력 항목 위의 장식성 소개 문구를 생략합니다.

## Android 위젯

- 소형 '한눈에': 가장 급한 미완료 일정 1건, D-day, 남은 준비물.
- 중형 '모아보기': 크기에 따라 2~3건, 진행 단계. 좁게 줄이면 소형 레이아웃 사용.
- 일정 탭: 해당 상세. `+`: 등록. 빈 상태 탭: 등록.
- 최종 완료는 제외. 기한 지난 미완료는 '기한 지남'. 일정이 없으면 빈 상태와 추가 버튼.
- 저장 직후 Android에 최소 표시용 스냅샷을 전달. 앱을 종료해도 Android가 표시·갱신.
- 30분 간격 갱신 요청, 날짜·시간대 변경 및 재부팅·앱 업데이트 시 다시 계산. 운영체제의 절전·강제 종료·런처 정책에 따라 갱신이 지연될 수 있으며 정확한 자정 실행을 보장하지 않습니다.
- Android 8 이상에서 지원 런처의 위젯 고정 요청 사용. 미지원 시 수동 추가 안내.
- Flutter 기본 딥링크는 끄고 위젯 전용 경로로 연결해 실행 중·종료 상태를 모두 처리.

구현 기준: [Android 위젯 개요](https://developer.android.com/develop/ui/views/appwidgets/overview), [갱신 정책](https://developer.android.com/develop/ui/views/appwidgets/advanced).

## 검수용 앱

`tool/preview.dart`는 예시 데이터를 넣는 별도 진입점입니다. **반드시 별도 applicationId 속성과 함께** 빌드하세요. 기존 앱과 저장 공간이 분리됩니다.

```sh
flutter build apk --debug -t tool/preview.dart --android-project-arg=chaengimPreview=true
```

일반 앱은 `flutter build apk --debug`로 빌드합니다. 검수용 APK가 생성된 뒤에는 일반 APK를 다시 빌드해야 합니다.

클라우드 백업은 아직 제공하지 않습니다. 위젯 빠른 체크는 기획서의 기본안대로 상세 화면으로 이동해 처리합니다. 이후 추가한 마감 알림의 규칙은 [알림 동작과 검수](reminders.md)에 정리했습니다.

## 초기 검수 기록

- `flutter analyze`: 지적 사항 없음. `flutter test`: 10개 통과.
- 320px 너비·글자 크기 1.6배에서 홈·일정 목록·위젯 가이드 오버플로 없음.
- Android 에뮬레이터에 설치해 앱 폰트·홈·상세 화면 확인.
- 실제 런처에 소형 2×2·중형 4×2 추가 확인. 중형을 세로로 확대해 3건 표시 확인.
- 위젯에서 첫 번째/두 번째 일정 상세 진입, +로 등록 화면 진입 확인.
- 앱 프로세스 종료 후 위젯으로 새 프로세스를 시작해 상세 진입 확인.
- 준비물 체크 후 남은 개수 동기화, 최종 완료 변경 후 해당 일정이 위젯에서 제외됨을 확인.
- 실물 휴대폰, 제조사별 런처, 재부팅 및 장시간 절전은 추가 검증 필요.

예시 데이터로 찍은 화면: [홈](screenshots/home.png), [상세](screenshots/detail.png), [기본 크기 위젯](screenshots/widgets.png), [확대한 중형 위젯](screenshots/widgets-expanded.png). 사용자 앱 데이터와 분리된 검수용 앱에서 촬영했습니다.

## 1.0.3 읽기 부담 줄이기

- 홈의 소개 문구·3종 집계·빈 준비물/다음 일정 안내·위젯 홍보 카드를 제거했습니다.
- 카드의 준비물 완료/남은 개수 중복 설명을 제거했습니다. 진행 막대의 읽기 보조 설명은 유지합니다.
- 일정 목록·마이·등록 화면의 장식성 소개 문구를 생략하고, 마이는 설정 메뉴 중심으로 줄였습니다.
- 상세의 중복 단계 그림을 없애고 진행 단계 선택을 유지합니다. 준비물 완료가 자동으로 최종 완료가 되지는 않습니다.
- 핵심 화면의 작은 11~13px 문구를 14px 이상으로 키우고 기본 본문은 16px로 조정했습니다. 보조 글자색을 진하게 해 5개 테마 바탕과의 계산 대비가 5.7:1 이상이 되게 했습니다.
- 코드 검사 지적 사항 0건, 테스트 43개 통과. 기존 320px·글자 1.6배 화면 검사와 저장·준비물 체크 흐름을 확인했습니다.
- 별도 검수용 앱의 예시 데이터로 Android 17 ARM64 변환 실행에서 [홈](screenshots/home-readable.png)·[마이](screenshots/my-readable.png)를 확인했습니다. 일반 배포용 APK는 예시 데이터를 넣지 않은 기본 진입점으로 다시 빌드합니다.

## 1.0.4 글꼴 조합

- 앱 상단 제목·큰 제목·홈 대표 일정에 마루부리 SemiBold를 사용해 종이빛 테마의 인상을 살렸습니다.
- 본문·일정 목록·버튼·날짜·D-day는 Pretendard를 사용합니다. 기본 본문은 Regular, 메뉴는 Medium/SemiBold, 마감 숫자는 Bold로 구분합니다.
- 이전의 음수 자간을 없애고 제목 줄 높이를 1.4로 맞췄습니다. 기본 본문 16px·줄 높이 1.5와 운영체제 글자 크기 설정을 유지합니다.
- 폰트를 원본 파일로 앱에 포함해 네트워크에 의존하지 않습니다. 두 글꼴의 저작권 고지·라이선스 전문을 포함하고 앱의 라이선스 화면에도 등록했습니다.
- 정적 분석 지적 사항 0건, Flutter 테스트 43개 통과. 기존 320px·글자 1.6배 검사는 실제 한글 폰트를 로드해 수행합니다.
- 별도 검수용 앱에서 [홈](screenshots/home-typography.png)·[상세](screenshots/detail-typography.png)와 [Android 큰 글씨 설정](screenshots/home-typography-large.png)을 확인했습니다. 일반 설치용 APK는 예시 데이터를 넣지 않은 기본 진입점으로 다시 빌드합니다.

## 1.0.5 라이드 앱 화면을 참고한 고딕체

- 사용자가 지정한 [라이드](https://ride.bz/) 모바일 앱의 차량비 수납 관리 이미지를 기준으로 제목·본문의 굵기 차이를 맞췄습니다.
- 라이드 공개 PC 앱의 [FontManifest.json](https://pc.ride.bz/assets/FontManifest.json)에서 Noto Sans KR 400/500/700을 확인했습니다. 모바일 앱의 내부 글꼴명은 스크린샷만으로 확정하지 않았습니다.
- 앱 글꼴을 Noto Sans KR로 통일하고, 큰 제목은 28px/24px Bold, 대표 일정은 22px Bold로 조정했습니다. 본문 16px Regular·줄 높이 1.5와 운영체제 글자 크기 설정을 유지합니다.
- Google Fonts에서 배포하는 원본 TTF와 OFL 1.1 라이선스를 앱에 포함합니다. 사용하지 않는 이전 글꼴 자산은 제거했습니다.
- 정적 분석 지적 사항 0건, Flutter 테스트 43개 통과. 320px·글자 1.6배 검사는 실제 Noto Sans KR을 로드해 수행했습니다.
- 별도 검수용 앱에서 [홈](screenshots/home-noto.png)·[상세](screenshots/detail-noto.png)와 [큰 글씨 설정](screenshots/home-noto-large.png)을 확인했습니다. 일반 배포 APK는 예시 데이터를 넣지 않은 기본 진입점으로 빌드합니다.

## 1.0.6 홈의 정보와 여백

- 홈에 이번 주 날짜와 미완료 마감 점·건수를 추가했습니다. 오늘을 강조하고 날짜를 누르면 해당 날의 일정 목록으로 이동합니다. 날짜·완료 상태·카테고리·검색을 함께 적용할 수 있고, 날짜 칩의 삭제 버튼으로 날짜 조건을 해제합니다.
- 빈 홈에는 지원·신청 / 시험·자격증 / 생활 빠른 추가를 제공합니다. 카테고리만 미리 선택하며 저장하기 전에는 일정을 생성하지 않습니다.
- 상단과 대표 카드의 여백, 준비물 행 간격을 줄였습니다. 빈 상태 카드는 더 작게 구성해 빠른 추가가 자연스럽게 이어지도록 했습니다. Noto Sans KR과 본문 글씨 크기를 유지합니다.
- 정적 분석 지적 사항 0건, 전체 Flutter 테스트 46개 통과. 주간 날짜 선택·필터 해제, 월 경계·완료 제외, 빠른 추가의 실제 저장을 검증했습니다. 마지막 빈 상태 간격 조정 후 해당 레이아웃·동작 검사 5개를 다시 통과했습니다.
- 실제 한글 폰트를 사용한 320px·글자 1.6배 검사에서 일정이 있는 홈과 빈 홈의 넘침이 없었습니다.
- Android 에뮬레이터에서 [일정이 있는 홈](screenshots/home-week.png), [날짜별 목록](screenshots/home-week-filtered.png), [큰 글씨](screenshots/home-week-large.png)를 별도 검수용 앱으로 확인했습니다. 일반 릴리스 앱에서도 실행과 [빈 홈](screenshots/home-week-empty.png)을 확인했습니다. 예시 데이터는 일반 APK에 포함하지 않습니다.
